# 顧問報告研讀：與現行實作的差距分析（2026-10-26）

**來源**：使用者提供的《香港小學中文筆順練習簿平台：完整語言學與教育顧問報告》
**用途**：把報告的 R1–R14 對照現行程式與資料，標示「已符合／需調整／未做」，供下一階段排期。

---

## 一、報告最關鍵的五個轉向

1. **「正字」降格為「代表字形」**：EDB 動畫是工程上的代表字形，不等於文字學上的唯一正字。全站文案（含介面標籤、說明頁、頁腳）都要由「香港教育標準」改成「香港教學參考字形／指定香港教學模式的優先採用形式」。
2. **資料、標準、呈現三層分離**：同一份字形資料可以服務不同教學情境，呈現層才決定學生看到甚麼；日後換政策不必重做字庫。
3. **關係分類 ≠ 來源分類**：`variant_character`／`glyph_variant`／`regional_form`／`simplified_traditional`／`unverified` 要與「資料來源」分開記錄，並各自帶 `status`（已核實／待核實）。
4. **筆畫數要拆三欄**：`glyph_stroke_count`（字形實際筆數）、`standard_stroke_count`（指定標準的教學筆數）、`worksheet_stroke_count`（工作紙實際使用）。三者不一致時**不可靜默選一個**，要標記待核實。
5. **未核實即不可宣稱已符合香港標準**：後備字形（twpen／HanziWriter）要保留來源與核實狀態，並依 A–D 品質分級標示。

---

## 二、逐條對照（R1–R14）

| 規則 | 現況 | 判斷 |
|---|---|---|
| R1 EDB 為首選來源但非唯一正字 | 權威順序 EDB ＞ twpen ＞ HW 已落地；但介面仍寫「香港教育標準」 | **需調整文案** |
| R2 分開儲存輸入字／顯示字形／關係 | `data/variant_pairs.json` 已有 `char / standard / alts / relation / own_glyph`；輸入原字保留在卡片 `data-char` | **部分符合**，缺 `status`、`source`、品質分級 |
| R3 不再一律稱異體字 | 已改「另一常見寫法」；內部關係只分「部件位置變體／同字異寫」 | **需擴大分類**至報告的五類 |
| R4 字形筆數 vs 教學筆數分開 | `CHAR_DB.s` 單一欄位（跟字形）；另有 `REGION_NOTES` 說明地區差異 | **未符合**，需拆三欄 |
| R5 未核實不得標為已符合香港標準 | twpen／HW 已標「參考字形」＋來源碼 | **大致符合**，但缺「待核實」狀態 |
| R6 保留輸入字形預設關、僅通過驗證可切換 | 「顯示我輸入的寫法」預設關；12 字可切換、8 字暫停 | **已符合** |
| R7 後備字形保留來源及核實狀態 | 字卡有 `EDB／TW／HW` 來源碼（含 title 全文）＋教師附錄 | **部分符合**，缺核實狀態；且來源碼會印落工作紙（與 R11 衝突，見下） |
| R8 粵音以香港資料為主，字形筆順另核 | 粵音 CUHK 為主、HKSCS 用 Unihan＋Wiktionary 覆核 | **已符合**，未在介面標示讀音來源 |
| R9 主讀音加詞例、其他可展開 | 今日已改：主讀一行，「又讀」折疊（列印隱藏） | **部分符合**：有折疊，但**無詞例資料** |
| R10 標點佔格、不納入逐筆描紅 | 標點佔一格、無筆順數字、不計筆畫 | **已符合** |
| R11 學生工作紙用整體來源聲明 | 頁腳有統一聲明；但 2026-10-26 新增了逐字來源碼，會印出 | **衝突，需調整** |
| R12 教師檢查模式（逐字來源／狀態） | 有教師附錄（270 列）＋ hover title | **部分符合**：未做到「點字查看來源與核實狀態」 |
| R13 簡繁轉換保留原字串與轉換依據 | `toTraditional()` 直接覆寫 `#inputText`，原始輸入不保留 | **未符合** |
| R14 建立爭議個案清單、逐字核實 | 有 21 組清單、8 組暫停、33 字筆數說明（在附錄） | **部分符合**：未標「核實狀態」欄 |

## 三、與今日已上線改動的兩個直接衝突

1. **逐字來源碼印落工作紙**：報告 R11 明確建議學生工作紙保持整潔、把來源放在教師檢查模式。現時 `EDB／TW／HW` 徽章會出現在列印稿。
   → 建議改為 **螢幕顯示、列印隱藏**，另在頁腳保留統一聲明。
2. **「香港教育標準 N 畫」字眼**：報告要求改為「香港教學參考字形」，並避免暗示已核實。
   → 建議字卡改「香港教學參考字形 N 畫」／「後備字形 N 畫」；未核實者加「待核實」。

## 四、資料層具體差距（工程規格）

現時每字只有一筆資料（`data.js` 的 `{jy,py,s,si}` + `glyph_sources.json` 的來源 + `variant_pairs.json` 的關係）。報告要求的完整欄位如下（可放 `data/char_meta.json`，由腳本生成，前端按需載入）：

```
character              原始輸入字元
display_glyph          實際顯示字形（可與 character 不同）
preferred_glyph        香港教學參考字形
relationship.type      variant_character | glyph_variant | regional_form |
                       simplified_traditional | unverified
relationship.status    verified | needs_review
source                 EDB | twpen | HanziWriter | 字體
quality_grade          A | B | C | D（報告第四節）
stroke.glyph          字形實際筆數
stroke.standard       指定標準教學筆數（未核實留空）
stroke.worksheet      工作紙實際使用（＝glyph，需與上者一致才標「已核實」）
order.source           EDB | twpen | HanziWriter | zdic
pron.jy / pron.py      主讀
pron.alts[]            又讀（含詞例，暫無資料）
pron.source            CUHK | Unihan | Wiktionary
verified_by / verified_at / note
```

**資料缺口**（需要新資料源，非改程式可解決）：
- 讀音詞例（每個讀音對應詞語）——報告 R9 要求，現時完全沒有。
- 「教學筆數」權威值：需要《常用字字形表》或課本級資料；現時只有字形實際筆數。
- 8 組替代字形（衛、蔥、蘊、醞、裡、鉤、溫、床）需人工核實筆數後才能開放。

---

## 五、建議落地次序（沿用報告階段，配合現有工具）

**第一階段（1–2 日，不動字庫）**
1. 文案再降級：全站「香港教育標準」→「香港教學參考字形」；新增「後備字形」「待核實」兩個標籤。
2. 來源碼改「螢幕顯示、列印隱藏」；頁腳統一聲明按報告建議改寫。
3. 建立 `data/char_meta.json` 骨架（用現有 `glyph_sources`／`variant_pairs`／`CHAR_DB` 生成），加入 `relationship.type/status`、`quality_grade`、三欄筆數（未核實留空）。
4. `toTraditional()` 保留原始字串並記錄所用詞組（R13）。

**第二階段（需人工判斷，逐步做）**
5. 逐字核實高風險清單：21 組爭議字 → 8 組暫停字 → 33 個筆數差異字 → 為／撝／臺／台 → 粵語字。每字填 `status`、`note`、`verified_by`。
6. 有核實結果才把 `quality_grade` 由 C 升 B／A，介面標籤跟隨。

**第三階段（呈現層）**
7. 教師檢查模式：點字卡顯示來源、筆順來源、筆數依據、關係與核實狀態（用 `char_meta.json`，不增加列印負擔）。
8. 詞例資料接入後，把又讀由「只有讀音」擴展為「讀音＋詞例」。

---

## 六、維持不變

- 字形、筆順、筆數的權威順序（EDB ＞ twpen ＞ HanziWriter）。
- 不推導字形出貨（報告 P8 認同）。
- 8 組替代字形維持暫停（報告 P7 認同「寧缺勿亂」）。
- 標點佔格但不做逐筆描紅。

---

*本分析只對照報告與現行程式，未對個別漢字作文字學裁定；凡未核實者一律標「待核實」。*
